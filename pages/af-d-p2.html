Связанные этапы, циклы и контроль

← Темы направления

Многие рабочие задачи состоят не из одного действия, а из нескольких этапов: получили информацию, обработали её, проверили результат, приняли решение и передали дальше. Если ИИ участвует только в одном таком этапе, всё довольно просто. Но когда он начинает работать сразу в нескольких местах, важно уже не только то, что именно он делает, но и как этапы связаны между собой.

Здесь речь уже не просто о доработке одного ответа в диалоге. Теперь несколько этапов самой работы зависят друг от друга, а между ними появляются проверки, решения и возвраты.

Результат одного этапа становится началом следующего

Допустим, компания получает документы от клиентов. Работа может выглядеть так:

получить документ → извлечь нужные данные → проверить их → определить проблему → подготовить результат → передать сотруднику

Если ИИ участвует в нескольких этапах, каждый следующий шаг зависит от предыдущего. Например:

ИИ извлёк данные → проверил их по правилам → отметил отклонения → подготовил краткое объяснение

После этого человек уже работает не с исходным документом, а с подготовленным результатом. То есть важно не только хорошо выполнить каждый отдельный шаг. Нужно, чтобы результат одного шага подходил для следующего.

Между этапами появляются точки контроля

Не каждый результат ИИ стоит сразу передавать дальше. Иногда следующий шаг можно выполнять автоматически. Иногда сначала нужна проверка человека. Например:

ИИ получил документ → выделил нужные данные → человек проверил важные значения → ИИ подготовил итог
Или: ИИ подготовил ответ клиенту → человек посмотрел его → ИИ отправил письмо после подтверждения

В другом процессе контроль может понадобиться только тогда, когда возникло исключение:

всё соответствует правилам → работа продолжается дальше

что-то не совпало → подключается человек

Так человек не обязан вручную проверять каждое обычное действие, но остаётся там, где действительно нужно именно его решение.

Иногда работа возвращается назад

Не все процессы идут только вперёд. Допустим, ИИ подготовил результат, а человек видит, что информации недостаточно. Тогда работа может вернуться на предыдущий шаг:

задача → работа ИИ → проверка → уточнение → новая работа ИИ → повторная проверка

Это уже цикл. Такие циклы постоянно встречаются и без ИИ. Сотрудник подготовил документ — руководитель вернул его на исправление. Поставщик прислал предложение — появились дополнительные вопросы. Клиент посмотрел вариант — попросил изменить условия. С ИИ происходит то же самое. Просто часть работы внутри цикла можно выполнять быстрее.

Цикл нужен не всегда

Простую задачу нет смысла специально превращать в сложную схему. Если ИИ подготовил хороший результат и больше ничего делать не нужно, работа закончена. Цикл появляется тогда, когда результат нужно:

  • проверить;
  • дополнить;
  • согласовать;
  • изменить;
  • использовать для следующего решения;
  • вернуть на доработку.

Поэтому сам по себе цикл не делает работу лучше. Он полезен там, где так устроена сама задача.

Несколько этапов нужно координировать

Представим более длинную работу:

получить запрос клиента → найти данные → подготовить вариант решения → проверить условия → согласовать → подготовить документы → отправить клиенту

Здесь уже мало просто сказать: «Используем ИИ на трёх этапах». Нужно понимать: когда каждый этап начинается, что он получает на входе, какой результат должен передать дальше, где требуется проверка, кто принимает решение, что делать, если что-то пошло не так. Это и есть координация работы. Без неё несколько хороших действий могут всё равно плохо складываться в одно целое.

Человек может участвовать не в каждом шаге

Когда работа состоит из многих этапов, важный вопрос — где именно нужен человек. Например, нет смысла каждый раз вручную подтверждать, что ИИ нашёл нужный файл, если ошибка легко обнаруживается позже и ничего серьёзного не произойдёт. Но перед отправкой важного документа клиенту проверка может быть необходима. Поэтому человек может подключаться не постоянно, а в определённых точках:

где высока цена ошибки; где требуется решение; где есть исключение; где действие трудно отменить.

Остальные этапы могут проходить без постоянного вмешательства.

Что важно понять на этом уровне

Когда ИИ участвует в нескольких частях работы, важно смотреть уже не только на отдельные запросы. Нужно видеть всю цепочку:

что запускает работу → какие этапы идут дальше → что передаётся между ними → где нужен контроль → где принимается решение → когда работа возвращается назад

Так отдельные действия начинают складываться в связанную систему. И здесь появляется следующий шаг. Если такая схема хорошо работает и нужна не один раз, возникает вопрос: как сделать так, чтобы она не зависела каждый раз от памяти и импровизации конкретного человека?
То есть как превратить удачный способ работы в повторяемый процесс.
